lesson -2
SDLC (SOFTWARE DEVELOPMENT LIFE CYCLE)
REQUIREMENTS - GATHER ALL THE USES AND NEEDS OF THE PROJECT
DESIGN - PREPARE THE FLOW HOW TO DESIGN THE PROJECT
DEVELOPMENT - DEVELOPERS BUILD THE CODE FOR PROJECT
TESTING - TESTERS TEST THE BUILD CODE
DEPLOYMENT - PROJECT WENT LIVE
MAINTANANCE - CHECKS THE PROJECTS IS EVERYTHING IS FINE OR NEED TO BE CHANGED
 TWO TYPES 
WATERFALL MODEL - TESTING CAN BE DONE ALL THE DEVELOPMENT IS COMPLETED. WHERE TESTING TAKES TIME
AGILE - IN AGILE MODEL WE CAN TEST THE PROJECT AT ANY TIME AFTER DEVELOPMENT OR MIDDLE. IN THIS PROJECT IS DIVIDED INTO SMALL SPRINTS WHICH IS USUALLY 2 WEEKS. WE CAN FIX ERROR EVEN IF THE DEVELOPMENT FINISHES

STLC (SOFTWARE TESTING LIFE CYCLE)
REQUIREMENTS - FIRST WE NEED TO GATHER ALL THE INFORMATION OF THE PROJECT
TEST PLANNING - THEN START THE PLANNING OF THE PROJECT WHAT HOW WHEN 
TEST CASE - DESIGN THE TEST CASES ACCORDING TO THE REQUIREMENT AND PROJECT
ENVIRONMENT SETUP - NEED TO SETUP THE ENVIRONMENT FOR TESTING
TEST EXECUTION - EXECUTE AND RECORD/ IMPLEMENT THE TEST CASES
TEST CLOUSER - READY THE REPORTS AND STATUS OF THE TEST CASES

Equivalence partitioning: test one value from each group.
Boundary value analysis: test just below, on, and just above each edge.
The requirement decides pass or fail, not what the page happens to do.
Test data should isolate one thing at a time.

Your reason for 16, “higher than the condition”, is right. Make it more precise in your notes: “16 is one above the maximum allowed length of 15.”

Why these six values

You tested on and next to each edge. This is the core of boundary value analysis:

Lower edge: 7 (just outside), 8 (on the edge), 9 (just inside)
Upper edge: 14 (just inside), 15 (on the edge), 16 (just outside)

If a developer wrote length > 8 when they meant length >= 8, then 8 would wrongly fail, and only this technique catches that.
